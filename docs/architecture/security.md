# Безопасность

## Аутентификация
- Аутентификация построена на JWT.
- Демо-логин находится в `POST /auth/login`.
- Поддерживаются два фиксированных набора учётных данных:
  - `user/user` -> роль `USER`
  - `admin/admin` -> роль `ADMIN`

JWT содержит:
- `sub`: username
- `iat`: время выпуска
- `exp`: время истечения
- `roles`: список ролей

TTL токена задаётся через `app.security.jwt.ttl-minutes`, по умолчанию `120` минут.

## Авторизация
В `SecurityConfig` заданы следующие правила доступа:
- `/actuator/health/**` -> доступ без авторизации
- `/auth/**` -> доступ без авторизации
- `/subscriptions/**` -> роли `USER` или `ADMIN`
- `/admin/**` -> только `ADMIN`
- остальные endpoints -> только для аутентифицированных пользователей

## Практические замечания
- CSRF отключён, так как приложение работает в stateless JWT-режиме.
- Сессии не используются, `SessionCreationPolicy.STATELESS`.
- Секрет JWT хранится в `application.yml`; для production его нужно вынести в безопасное внешнее хранилище.
- В текущем коде пути контроллеров начинаются с `/api/...`, поэтому правило `/subscriptions/**` не покрывает endpoint `POST /api/subscriptions`. Это важно учитывать при дальнейшей настройке access rules.
